# Generative Modeling by Value-Driven Transport

Code for the experiments of [*Generative Modeling by Value-Driven Transport*](https://arxiv.org/abs/2605.22507) (Pablo Moreno-Muñoz, Adrian Müller, Gergely Neu).
A value function is trained with a primal-dual method on the linear-programming formulation of discrete-time dynamic optimal transport, and samples are generated by following the gradients of the learned value function (value-driven transport, VDT).

## Installation

```bash
python -m pip install -e .
```

On GPU machines, install a PyTorch build that matches your CUDA driver first.
All commands below are run from the repository root.
All configs set `device: cuda`; change `device` in the config (e.g. to `cpu`, `mps` or `auto`) to run elsewhere.

MNIST and EMNIST are downloaded automatically to `data/`; CelebA is loaded with `torchvision.datasets.CelebA` from `data/celeba/` (if the automatic download fails, place the CelebA files there manually).
On first use, the cropped and downsampled CelebA images are cached in `data/celeba/preprocessed/`.

## Code structure

```
src/dynamicot/
  primals/       particle initialization (random or minibatch-OT coupling), batching, primal updates (Eq. 7)
  duals/         value-function models, dual objective (Eq. 8), training loops, VDT generation (Algorithm 2)
  data/          2D benchmarks, MNIST/EMNIST, CelebA
  experiments/   one entry point per experiment (train -> evaluate -> plot), plus separate eval/plot modules
  utils/         config, I/O, runtime helpers
configs/         one YAML config per experiment
scripts/         plotting scripts for trained checkpoints
```

Every training run writes to `results/<experiment>/results_<timestamp>/`: the config (`experiment_config.json`), training metrics, checkpoints (including EMA weights where used), evaluation artifacts and plots.
Evaluation and plotting can be re-run on an existing run, e.g. `python -m dynamicot.experiments.dual_emnist_mnist_eval --results-dir <results_dir>`.

## Experiments

| Paper | Command |
| --- | --- |
| 2D experiments (Table 1, Table 2) | `python -m dynamicot.experiments.dual_2d --config configs/dual_2d_table.yaml` |
| MNIST deblurring, $m \in \{6, 10, 14\}$ | `python -m dynamicot.experiments.dual_mnist_upsample --config configs/dual_mnist_upsample_6.yaml` (and `_10`, `_14`) |
| Unpaired EMNIST → MNIST translation | `python -m dynamicot.experiments.dual_emnist_mnist --config configs/dual_emnist_mnist.yaml` |
| Conditional MNIST generation with guidance | `python -m dynamicot.experiments.dual_mnist_guidance --config configs/dual_mnist_guidance.yaml` |
| CelebA $32 \times 32$ | `python -m dynamicot.experiments.dual_celeba --config configs/dual_celeba.yaml` |

The 2D command trains and evaluates every data set with random (`linear`, VDT) and minibatch-OT (`ot`, VDT+) particle initialization over 5 seeds, and writes the squared Wasserstein-2 distances and path energies for all test horizons to `results_summary.csv`.

The CelebA configuration (batch size 258, horizon 30) does not fit into the memory of a single standard GPU.
Lowering `training.time_chunk_size` processes the time steps in chunks and reduces the memory requirement without changing the computation (up to floating-point rounding).

## Plotting

The plotting scripts load a trained checkpoint and plot samples generated from fresh inputs (held-out test images or new source samples). Set `checkpoint_path` in the script's config (absolute, or relative to the repository root) and run:

| Experiment | Command |
| --- | --- |
| MNIST deblurring, $m \in \{6, 10, 14\}$ | `python scripts/final_upsample_plots.py --config configs/final_upsample_plots.yaml` (once per $m$) |
| Unpaired EMNIST → MNIST translation | `python scripts/final_emnist_mnist_plots.py --config configs/final_emnist_mnist_plots.yaml` |
| Conditional MNIST generation with guidance | `python scripts/final_conditional_guidance.py --config configs/final_conditional_guidance.yaml` |
| CelebA $32 \times 32$ | `python scripts/final_celeba_plots.py --config configs/final_celeba_plots.yaml` |

In the paper, we use the EMA weights (`checkpoints/checkpoint_final_ema.pt`), except for deblurring, where we use `checkpoints/checkpoint_final.pt`.
The plots are written to `results/final_*/results_<timestamp>/`.
